# 本地 Office/WPS 联动：安全说明（阶段 6）

> 这份文档回答「插件凭什么敢在你机器上启动 Office/WPS」，逐条对应《开发要求》
> §十二.4「Office/WPS 自动化安全」与 §十七 阶段 6 的验收要求。
> 设计与实测记录见 [README「本地 Office/WPS 联动」](../README.md#本地-officewps-联动阶段-6)。

## 一、总原则

1. **默认关闭**：`allowLocalAutomation` 不是 `true` 时，`office_recalculate` / `office_rerender`
   一律返回 `AUTOMATION_DISABLED`，并说明怎么开。唯一不需要授权的是
   `office_detect_engines` **不带 `probe_com`** 的只读注册表检测（它不启动任何程序）。
2. **只碰副本**：输入文件**只读打开**；产物写到调用方指定的新路径（默认落在插件的受管输出目录）。
   工具会明确拒绝「输出路径 = 输入路径」。
3. **不做不可见的事**：每一次调用都返回引擎名与版本、耗时、被清理的 PID、残留 PID、审计已记录标记；
   失败时返回结构化错误码而不是「看起来成功」。

## 二、逐条对照

| 开发要求 | 落地方式 | 可核对之处 |
|---|---|---|
| 使用独立进程或受限账户 | 引擎在自己的进程里跑；插件侧只通过**结果 JSON 文件**读结论（不捕获管道输出，不共享内存、不暴露 COM 对象） | `lib/automation.js` 的 `#invoke`；`-NonInteractive` + `stdio: 'ignore'` |
| 禁止宏自动执行 | `AutomationSecurity = 3`（`msoAutomationSecurityForceDisable`）；宏文件按宏格式重存（52/13/25），宏代码按字节保留但从不执行 | `lib/office-automation.ps1`；测试 `MACRO_NOT_EXECUTED` 警告 |
| 禁止外部链接自动更新 | `AskToUpdateLinks = false`，打开时 `UpdateLinks:=0` | 同上 |
| 禁止外部模板自动加载 | 插件从不调用 `AddIns` / `AttachedTemplate`；不打开任何模板文件 | 脚本里没有这两个入口（可全文检索） |
| 设置脚本执行超时 | 默认 120 s（`automationTimeoutMs` 可调，单次可传 `timeout_ms`）；到点先杀 PowerShell 进程树，再用状态文件补一次 `cleanup` | 单测「超时：终止本次调用并补一次 cleanup」 |
| 防止弹窗阻塞任务 | `DisplayAlerts = false`、`-NonInteractive`、尽量 `Visible = false`（PowerPoint 不支持隐藏，会如实返回警告） | 脚本里的四道开关 + `warnings` |
| 检测软件进程异常退出 | 结果以「脚本是否写出 JSON 且 `ok=true`」为准；没有结果文件即 `AUTOMATION_FAILED` | 单测「脚本没写结果文件 → AUTOMATION_FAILED」 |
| 任务结束后清理相关进程 | 开始前快照引擎 PID，结束后**只杀新增的 PID**（5 轮轮询，WPS 会懒启动 worker），并回报 `killed_pids` / `leftover_pids` | 真机验证断言 `leftover_pids` 为空；同时不会误杀用户在用的 Office/WPS |
| 文件锁避免并发修改同一文件 | 调用期间对源文件持有插件自己的文件锁（`FileLock`），与其它工具共享同一套锁语义 | `lib/tools.js` 的 `runEngineRewrite`；并发套件 |
| 对本地自动化操作进行审计 | 每次调用追加一行 JSONL 到 `.dsh-exp-office/audit/office-automation.jsonl`：时间、动作、引擎、**文件名（不含路径）**、字节数、耗时、成功与否、错误摘要、残留 PID | 单测断言「不含绝对路径」；真机验证同样断言 |

## 三、日志里有什么、没有什么

```json
{"time":"2026-09-23T11:44:07.512Z","action":"recalc","engine":"excel","input_name":"stale.xlsx","output_name":"excel-recalc.xlsx","ok":true,"error":null,"elapsed_ms":3483,"output_size":10318,"leftover_pids":[]}
```

- **有**：动作、引擎、文件名、字节数、耗时、结果、残留进程 —— 足够回溯「谁在什么时候动了什么」。
- **没有**：绝对路径、文档正文、单元格内容、批注/修订文字。开发要求 §12.3「日志中不得输出完整文档内容」
  与「敏感信息脱敏」按此执行。

## 四、明确没做的（不是遗漏，是边界）

1. **受限账户/沙箱隔离**：需要一个专用低权限账户或容器来跑 Office，属于运维层面；插件只能保证
   「独立进程 + 只碰副本 + 超时清理」。要更硬的隔离，请把插件跑在受限账户下（那时这条自动满足）。
2. **视觉回归**：判断「重算/重渲染后版式有没有变」需要把文件渲染成图片再比对，本机没有可用的
   光栅化器（见 [OCR 能力核查](OCR能力核查.md) 的证据），因此只做结构级校验，并把这一点写进
   `verification.not_verified`，不假装做过。
3. **把 Office/WPS 内部对象暴露给上层 Agent**：开发要求明令禁止，插件只返回结构化结果。
4. **Word 启动时可能加载你自己 Startup 目录里的加载项**：这是 Word 自身的行为，插件不加载任何模板，
   但无法阻止 Word 加载用户级加载项；要彻底避免请用受限账户或干净配置运行。

## 五、复现命令

```bash
npm run test:automation     # Node 侧：开关 / 超时 / 进程回收 / 审计（桩脚本，不启动 Office）
npm run verify:automation   # 真机：真实 Excel/WPS/Word/PowerPoint（会启动本机 Office）
```

真机验证最后一次运行的结论：Excel 与 WPS 都把故意写错的公式缓存（999）重算成了 3；
Word / PowerPoint 重写后的产物能被自身读取器解析且规模一致；源文件逐字节未变；无进程残留。
