# 发布检查单

每次发版按这张单子走一遍。**任一条不过就停**，不要带着问题发布。

## 0. 前置：一次性准备（每台机器一次）

- [ ] 凭据：PAT 放进 `%USERPROFILE%\.dsh\secrets\github.env`（模板见 `github-release` 技能的 `assets/github-env.template`）
  - 权限：**Contents: Read and write**（推送）+ **Administration: Read and write**（新建仓库）
  - **令牌不写进 remote URL、不写进 `.git/config`、不写进任何入库文件**；只通过进程环境变量喂给 git 的 credential helper
- [ ] git 身份：`git config --global user.name` / `user.email`（建议用 GitHub 的 noreply 隐私邮箱）
- [ ] 本地隐私模式表：`.privacy-patterns.local`（一行一个模式，**绝不入库**）

## 1. 代码与测试

- [ ] `npm test` —— 11 个套件全绿
- [ ] `npm run test:convert` —— 转 PDF 套件（需要宿主引擎）
- [ ] `npm run test:perf` —— 性能基准达标
- [ ] `npm run verify:pack` —— 打包产物文件齐全、零依赖、可装载
- [ ] `npm run verify:lifecycle` —— 安装 → 升级 → 卸载 演练通过（含「未改动源码」断言）

## 2. 真机验证（改了哪个格式就跑哪一组）

- [ ] XLSX：`npm run verify:excel` / `verify:wps` / `verify:table` / `verify:chart`
- [ ] DOCX：`npm run verify:word` / `verify:docx-table` / `verify:docx-table-build` / `verify:docx-layout` /
      `verify:docx-wrap` / `verify:docx-bookmark` / `verify:docx-export`
- [ ] PPTX：`npm run verify:pptx` / `verify:pptx-image` / `verify:pptx-slide-ops` / `verify:pptx-layout` /
      `verify:pptx-theme` / `verify:pptx-charts` / `verify:pptx-created` / `verify:pptx-created-edited`
- [ ] WPS 交叉：`pwsh -File test/wps-office-check.ps1 -Path <文件> -Kind writer|presentation`
- [ ] PDF：`npm run verify:pdf` / `verify:pdf-form` / `verify:pdf-annotation`，以及
      `pwsh -File test/pdf-open-check.ps1 -Path <pdf> -Match <ASCII 关键词>`

## 3. 发布闸门（三连检，缺一不可）

- [ ] `npm run verify:privacy` —— 隐私扫描：0 命中（个人信息、本机用户路径、noreply 邮箱）
- [ ] `pwsh -File <skill>\scripts\github-secret-scan.ps1 -ProjectPath . -StagedOnly` —— 敏感信息：BLOCKER=0
- [ ] `pwsh -File <skill>\scripts\github-repo-check.ps1 -ProjectPath . -StagedOnly` —— 打包规范：无 BLOCKER
- [ ] 有命中就**停下来问**：不自行判断「这条应该没事」，也不改扫描规则放行；
      误报优先考虑**改代码消除**（例如把 `const token = …` 改名为 `word`），而不是给文件开例外

## 4. 版本与文案

- [ ] 版本号：`package.json` 与 `dsh.plugin.json` 的 `version` 一致
  - 首次发布 `0.1.0`；修 bug 递增 PATCH；加功能递增 MINOR；破坏性改动递增 MAJOR
- [ ] `CHANGELOG.md` 补上本版条目（新增能力 / 修复 / 已知限制）
- [ ] `README.md` 的工具数、测试断言数、验证矩阵与目录结构同步更新
- [ ] 需要英文 README 时同步 `README.en.md`

## 5. 提交与推送（每步单独确认）

- [ ] `git add -A` → 把**完整文件清单**给用户看 → 用户确认 → `git commit`
- [ ] `git push`（需要一次放开沙箱：git 要给传输助手建管道）+ 打 tag（`v0.1.0`）→ 用户再确认一次
- [ ] 推送输出核对：无 `403`/`Authentication failed`/`rejected`
- [ ] 用 `git ls-remote` 复核远程 refs 与本地一致

## 6. 收尾

- [ ] 删除 `.dsh-release/`（运行残留与扫描报告），确认它从未入库（`.gitignore` 已覆盖）
- [ ] 确认工作区只剩预期文件（无临时脚本、无 staging 目录、无锁文件）
- [ ] 确认没有残留的 Office / LibreOffice 进程
- [ ] 把发布结果（仓库链接、tag、commit 短哈希、扫描结论）汇报给用户

## 附：本机实测踩过的坑（写在这里免得下次再踩）

| 现象 | 原因 | 处理 |
|---|---|---|
| `npm install file:C:/…/x.tgz` 报 ENOENT | npm 会把盘符绝对路径解析坏（日志里变成 `file:C:Users…`） | 依赖里一律用**相对路径**，或把 tarball 当普通路径传给 `npm install` |
| 「升级」后旧文件还在 | 同版本不会触发替换 | 真升级演练必须**递增版本号** |
| 改「安装副本」的文件，结果改了工作区源码 | `file:<目录>` 依赖装出来是**符号链接** | 演练里对源码做指纹断言（`verify:lifecycle` 已内置） |
| 隐私扫描把源码里的 `const token = …` 当密钥 | 规则按「token/密码赋值」匹配 | 变量改名（不是给扫描开例外） |
