# 审计日志

> 目标：回答「**谁、什么时候、调了哪个工具、动了哪个文件、成功没有、花了多久**」——
> 而不把文档内容或本机目录结构写进日志。

## 怎么开

插件配置（默认**关闭**）：

```jsonc
{
  "auditLogEnabled": true,
  // 可选，默认 <workspaceRoot>/.dsh-exp-office/audit/office-tools.jsonl
  "auditLogPath": "audit/office-tools.jsonl",
  // basename（默认，只留文件名）| relative（工作区相对路径）
  "auditLogPathMode": "basename",
  // 单文件上限，默认 8 MB，超过轮转为 office-tools.jsonl.1
  "auditLogMaxBytes": 8388608
}
```

## 记了什么

装载时一条事件：

```json
{"time":"2026-09-28T03:55:12.345Z","source":"plugin","event":"registered","plugin_version":"0.1.0","tools":90,"path_mode":"basename"}
```

每次工具调用一条：

```json
{"time":"2026-09-28T03:55:12.401Z","source":"tool","tool":"office_create_pdf","plugin_version":"0.1.0","duration_ms":59,"target":"report.pdf","ok":true,"request_id":"req-...","changes_count":1,"output_bytes":18633}
```

| 字段 | 含义 |
|---|---|
| `time` | ISO 时间（UTC） |
| `source` | `plugin`（装载事件）或 `tool`（工具调用） |
| `tool` | 工具名 |
| `duration_ms` | 该次调用耗时 |
| `ok` | 成功为 `true`；失败走 `error_code` |
| `error_code` | 结构化错误码（如 `FILE_NOT_FOUND`）；工具真抛异常时记 `THROWN` 并附带截断后的 `error_message` |
| `target` | 这次调用指向的文件/目录，按 `auditLogPathMode` 记录 |
| `request_id` | 与工具返回值里的 `request_id` 对应，便于串联 |
| `changes_count` / `output_bytes` | 有变更列表 / 有输出文件时附带 |

## 三条硬约束（都有测试盯着）

1. **只记元数据**：不写文档正文、不写单元格值、不写文件内容。
2. **默认不带目录**：`basename` 模式下绝对路径只留文件名；`relative` 模式下**工作区之外**的路径也退回文件名 ——
   审计日志不应该泄漏本机目录结构。测试里有一条硬断言：整份日志里**不允许出现盘符路径**。
3. **审计绝不拖累工具**：写盘失败只累加 `writeErrors` / `lastError`，工具照常返回；
   工具真抛异常时也先记一行再把异常抛出去。

## 独立性

日志是**标准 JSONL**，不依赖插件自己的解析器。仓库里的独立验证（`npm run verify:audit`）
用 **.NET 的 JSON 解析器**（PowerShell `ConvertFrom-Json`）逐行读回，断言：

```text
PARSED_ROWS 4   TOOL_ROWS 3   REGISTERED 1   FAILED_ROWS 1   HAS_DURATION 3   ABS_PATH_HITS 0
```

这一层是必要的：用 Node 读自己写的 JSON 只能证明「自己写的自己认」。

## 与「本地联动审计」的关系

驱动本机 Office/WPS 的那条路（`allowLocalAutomation`）另有一份更细的审计
（`office-automation.jsonl`：引擎、动作、输入输出文件名、退出码），见
[本地联动安全说明](本地联动安全说明.md)。两者不重复：

- **统一操作审计**回答「这个插件被怎么用了」（工具级）；
- **本地联动审计**回答「引擎那一侧做了什么」（引擎调用级，含超时与进程清理细节）。

## 轮转与容量

- 单文件超过 `auditLogMaxBytes`（默认 8 MB）时轮转为 `<file>.1`，只保留一份备份（旧的被覆盖）；
- 轮转判断用一次 `statSync`，所以「一超限就轮转」，不需要额外配置；
- 想长期留存请用你自己的日志采集器接管这个文件（它是标准 JSONL，直接 tail 即可）。
